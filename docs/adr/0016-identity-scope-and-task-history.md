# 0016 租户内的用户隔离、显式事项成员与历史流程续接

日期：2026-11-11 · 状态：已采纳。取代 ADR 0012、0014 中“同部门审批人默认可访问事项”的规则。

## 身份与访问边界

租户代表组织空间，用户代表空间内的登录主体。单组织部署可以继续使用 `default` 租户；不需要给每个员工创建一个租户。所有身份字段仍来自经过验证的令牌，客户端不能通过请求体选择他人的空间。

`Principal.scope_key` 对 `[tenant, subject]` 做结构化编码后计算稳定哈希。私人聊天的锁、回执、工作记忆、情景记忆、画像更新和 SSE 所有权均使用该作用域。同一 `subject` 在不同租户中拥有独立记忆；换会话仍能召回本人在当前租户的历史。trace 同时验证租户和既有角色/所有者权限；缺少租户的旧 trace 不通过新入口读取。请求 ID 使用 `v2` 命名空间，避免分隔符碰撞。

所有审批读取、投票和替代旧申请操作校验租户，包括未关联共享事项的旧私聊审批。旧私聊审批继续使用租户内的审批角色策略；共享事项审批额外遵守事项成员与指定审批人规则。用户不能借旧 `/approvals` 入口访问被移除的共享事项。

共享事项仅对申请人、同租户 IT 管理员、显式协作者/观察者或指定审批人开放。同部门和审批角色本身不授予事项访问权。申请人或管理员可邀请已登录本租户的用户；邀请不授予组织审批角色。观察者不能发言、投票或继续流程。管理员指定审批人会授予事项访问权，未指定人员不能投票；取消指派会移除仅由指派带来的访问权。移除/降级成员或取消指派前，必须处理其未完成待办，避免留下无人能答复的任务。

## 历史事项与跨会话记忆

`TaskHistory` 提供按当前权限检索、实时摘要、关联和续接：

- 检索在 SQL 候选阶段应用租户和成员权限，读取摘要时再次校验。检索标题、结构化目标/结论和申请人消息；采用英文词与中文二元词组匹配，从最近 100 个匹配候选中返回最多 20 项。这是确定性关键词检索，不是全库语义召回。
- 摘要读取当前目标、进度、阻塞、未完待办、Agent 回合及审批/执行状态，不返回原始讨论。历史验收结论与当前状态分字段呈现。
- 私聊通过独立 `TaskRecall` 端口自动召回最多 3 个**本人发起的事项**。上下文标明这些内容是数据，历史批准不构成新的写操作授权。私聊响应返回可打开原事项的引用。
- 被邀请参与他人事项的用户通过网页实时搜索访问历史，不自动将这些事项复制到个人长期记忆。共享 Agent 不读取个人记忆，也不自动读取关联事项的内容。
- `task_links` 只保存关联关系。建立关联要求管理目标事项并有权读取源事项；关联不复制讨论，也不扩大访问范围。每位查看者都必须单独拥有源事项权限。共享事件不包含源事项 ID、标题或摘要；撤销源权限后接口不再返回该源事项。
- “继续只读跟进”向原事项写入幂等的 `continuation` 事件，重新读取当前进度、审批与执行状态。停止或已解决的事项只能由申请人/管理员重新打开；重新打开和排队事件在同一事务完成。已有审批不会重新创建或执行，新的业务变更仍需申请人明确发起并正式审批。

网页在私聊下方提供“查找并继续历史事项”，共享事项中提供“历史事项与关联流程”。切换身份或后端会重建控制器，丢弃迟到结果；继续流程响应丢失时保留请求键，避免重复排队。

## 解耦与持久化

| 模块 | 职责与依赖 |
|---|---|
| `core/scopes.py` | 纯身份作用域计算，不依赖数据库、HTTP 或 Agent |
| `TaskAccess` | 成员权限、目录和审批指派；通过访问策略接口注入 TaskStore |
| `TaskHistory` | 授权检索、引用和续接；注入进度服务与审批读模型，不调用路由或模型 |
| `TaskRecall` | 私聊上下文适配，只接收读取函数，不导入事项存储 |
| `memory/scope_migration.py` | 旧记忆的显式归属迁移，不依赖事项服务 |
| `task_history` 路由 | HTTP 校验和服务调用，通过共享依赖唤醒 worker |
| `taskClient` / `taskHistoryController` / `TaskHistoryPanel` | 分别负责传输、异步状态和展示；不直接提交审批 |

`TaskStore` 本身不导入产品访问策略，未注入扩展时只允许申请人和同租户管理员访问。`TaskCapabilities` 与 `api/main.py` 负责组装。迁移 `0011` 新增 `task_links` 和 `memory_scope_bindings`；它们分别由事项与记忆 schema 定义，审批状态不复制进历史表。

## 升级与旧数据

重启 API 会应用迁移。既有事项也立即使用显式成员规则：之前仅凭部门进入的审批人需要被邀请或指定，已有成员/指定审批人记录继续有效。历史投票、讨论与审批不会删除。

旧版只有 `subject` 的私人记忆保留在原位置，但不作为新作用域的兜底数据。不能仅凭同名用户猜测组织。运维可根据可信身份目录准备 JSON 映射，例如：

```json
[{"subject": "dev:alice", "tenant": "default"}]
```

先停止旧版本写入并备份数据库，再在已配置 `IT_COPILOT_DATABASE_URL` 的环境运行：

```bash
.venv/bin/python scripts/migrate_memory_scope.py --bindings /path/to/verified-bindings.json
.venv/bin/python scripts/migrate_memory_scope.py --bindings /path/to/verified-bindings.json --apply
```

第一条仅预览记录计数；第二条复制长期情景记忆和画像，保留源记录。绑定表禁止把同一个旧 `subject` 分配给多个租户；元数据中的已有租户必须与映射一致。重复执行不会重复复制或覆盖目标画像；多个旧画像选最近更新的一个，并报告冲突数。无法证明唯一归属的旧数据应保持隔离。

短期 Redis 会话、旧回执、旧 SSE 与无租户 trace 不迁移。升级前应等待在途请求结束，避免用旧请求键跨版本重试创建新的申请；已有审批继续按原审批 ID 读取和处理。升级后私聊开启新会话，按上述映射恢复可确认归属的长期记忆。

## 验证与范围

```bash
.venv/bin/pytest -o addopts='' -q tests/test_isolation_and_history.py
npm test --prefix frontend
.venv/bin/python scripts/evaluate_shared_tasks.py --repeats 3 --output /tmp/shared-isolation.json
```

相同后端契约通过 `IT_COPILOT_TEST_DATABASE_URL` 在 PostgreSQL 执行，包含同名用户跨租户、旧审批/trace/SSE 隔离、旧记忆迁移、成员撤销、指派与待办、逐查看者历史授权、并发幂等引用和只读续接。共享流程评测验证登录、邀请、投票及后续工作流，使用确定性处理器与隔离业务数据，不等同于浏览器、真实模型或真实 IdP 验证。

本决定覆盖聊天、记忆、事项与审批的应用权限。知识库和业务目录适配器仍需各自的租户映射，不能据此宣称全部外部系统都已具备独立租户资源。任务历史只包含共享事项，既有私人聊天仍由三级记忆模块召回。
