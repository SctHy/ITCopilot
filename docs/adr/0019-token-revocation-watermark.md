# 0019 按身份的令牌吊销水位线

日期：2026-11-12 · 状态：已采纳

## 背景

API 只校验令牌签名与有效期，不查询 IdP 吊销状态（威胁模型“令牌吊销与会话失效：依赖短有效期”）。员工离职、令牌泄露时，已签发的令牌在过期前仍然可用：Keycloak 访问令牌 15 分钟，开发令牌 8 小时。每个请求都去 IdP 做令牌内省会把 IdP 变成每次请求的依赖，开发令牌也没有内省端点。

## 决定

- 每个（租户, subject）一条水位线 `revoked_before`（`session_revocations` 表）。签发时间 `iat` 不晚于水位线的令牌一律拒绝（401），无论是否过期；之后重新登录拿到的令牌照常可用。水位线只前移不后退，进程时钟偏慢也不会撤销吊销。
- `iat` 是整秒，水位线取吊销时刻向下取整：同一秒内重新登录的令牌也会被拒，等一秒重试即可，换来的是“吊销前签发的令牌一定失效”。没有 `iat` 的令牌无法证明晚于吊销，按已吊销处理。
- 检查放在 `current_principal`，所有 HTTP 入口（含 SSE 续传、事项、审批）共用；早于事项身份目录的刷新，被吊销的人不会再更新目录。查询失败时拒绝请求（503，fail closed），与限流相反：这是认证决定。
- 每个进程缓存查询结果 5 秒（`IT_COPILOT_REVOCATION_CACHE_S`），吊销最晚在缓存窗口内对所有进程生效；执行吊销的进程立即生效。
- 入口：管理员 `POST /admin/sessions/revoke`（按 subject，或按本租户登录过的用户名，重名时要求改用 subject），本人 `POST /auth/logout-all`（退出所有设备），审计员/管理员 `GET /admin/sessions/revocations`。每次吊销写管理操作审计。

## 后果

- 这是本服务的会话失效，不是 IdP 的：离职仍需在 IdP 停用账号，否则此人可以重新登录。
- 飞书入口按映射表识别身份、没有令牌，不受水位线约束；离职时还要从 `config/feishu_users.yaml` 删除映射。
- 已在执行中的工作（审批通过后的动作、已排队的事项回合）不因吊销而取消；它们按审批与策略复核处理。
