# 0017 申请人撤回待审批申请与提前归还限时权限

日期：2026-11-12 · 状态：已采纳

## 背景

申请发起后，申请人只能等审批人处理或等到期：换了会话就无法用 ADR 0007 的替代机制收回误提交的申请。限时授权只能等到期回收，用完的权限仍然留在账号上，与最小权限原则相悖。两者都需要申请人主动收回，但不能绕过已有的并发、审计与漂移保护。

## 决定

- **撤回**（`POST /approvals/{id}/withdraw`）：新增审批终态 `withdrawn`（`pending → withdrawn`）。只有同租户的申请人本人可以撤回，审批人与管理员不能代撤（他们用拒绝）。与审批决定共用版本号 CAS：撤回与投票并发时只有一方生效；撤回后的投票按“已决定”幂等返回；重复撤回幂等。到期后撤回记为 `expired`，记录真实发生的事。状态、审计（`withdrawn`，可附理由）与 IM 通知同事务提交；共享事项把它当作终态并唤醒只读跟进。
- **提前归还**（`POST /approvals/{id}/release`）：申请人、权限持有人或同租户 IT 管理员可以归还该申请下仍生效的限时权限。实现上不新建回收动作，而是把授权生效时排好的 revoke 动作提前到现在（只改仍在排队且未到期的行），因此 worker 执行的仍是到期回收那一套：先查漂移，原有权限和被他人改动的权限不会被删。每项归还写审计 `grant_released`；没有可归还的权限（原有权限、待审批、漂移）返回 409，已归还过再调用幂等返回空列表。

## 后果

- 前端审批卡片对申请人显示“撤回申请”，对生效中的限时权限显示“提前归还权限”；仅是展示，服务端独立校验。
- 撤回不需要冻结哈希：它只会减少将要发生的变更，不会改变被批准的内容。
- 归还只覆盖本系统开通、仍有排期回收的授权；企业 IAM 里的其他权限不在范围内。
- 对话入口（`agents/request_recall.py`）：用户说“撤回”“归还”“用完了”“我的申请”等，或意图为权限复核时，服务端按身份查出本人可撤回的申请与可归还的授权，作为数据放进本轮上下文，并在响应的 `related_approvals` 里返回，网页显示对应卡片。Agent 没有撤回/归还工具：这两件事始终由本人点击完成，知识库注入最多让 Agent 提到这些项目，不能改变它们。飞书里只能提示用户到网页操作。
