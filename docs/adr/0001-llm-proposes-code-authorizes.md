# 0001 模型只提出变更，授权由确定性代码负责

日期：2026-10-28 · 状态：已采纳

## 背景

Agent 可以调用权限申请、密码重置、建单等写工具。模型输出会受用户输入和检索内容影响（提示注入），也会出错；如果模型的判断决定“能不能执行”，安全性就等于模型的鲁棒性。

## 决定

- 写工具只生成待审批记录（dry-run），不产生任何副作用。
- 能申请什么、谁能申请、需要几人批准、最长多久，由 `config/access_policy.yaml` 决定；工具调用时校验一次，审批库冻结时再校验一次，并记录策略版本。
- 批准只能由具备 approver / it_admin 角色、且与申请人和目标账号无关的人做出。
- 执行由 worker 依据冻结快照完成，与对话过程无关。

## 后果

- 知识库或用户输入中的“跳过审批”类文本无法提升权限；安全回归中的 `injection_kb_skip_approval` 用一个完全听从注入的模型验证这一点。
- 模型选错角色或系统时，结果是申请被拒或生成一个会被审批人看到的错误申请，而不是错误执行。
- 策略修改需要改配置并提升版本号，旧审批仍可按其记录的版本解释。
