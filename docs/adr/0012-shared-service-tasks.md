# 0012 三方共享事项：事件持久化、按事项串行、审批结果唤醒只读跟进

日期：2026-11-11 · 状态：已采纳

默认部门访问规则已由 [ADR 0016](0016-identity-scope-and-task-history.md) 取代；以下保留当时的决策记录。

## 背景

私人聊天以用户身份隔离，审批人此前通过独立审批列表处理申请，无法与申请人、Agent 共同讨论同一事项。动作 worker 能恢复业务操作，但审批完成不会自动回到原诊断任务。

借鉴 DeepSeek Super-agent 的工作与执行分离、事件唤醒和 stored work，在现有 PydanticAI 与审批链外增加持久化事项层。

## 决定

- `service_tasks` 保存事项与申请人的可信身份快照，`task_events` 保存共同讨论和结果，`task_runs` 保存需要 Agent 处理的回合。Alembic `0007` 创建表；工作流、消息与运行状态使用同一个应用数据库。
- `POST /tasks` 创建共享事项；`POST /tasks/{id}/messages` 添加讨论，`ask_agent=false` 只记录讨论。创建和发言均要求 `client_request_id`，同一键内容变化返回 409。正文中的身份字段不参与授权。
- 事项对申请人、同部门审批人、同租户 IT 管理员可见。列表、详情、消息、重试、停止与审批均校验对象权限；旧 `/approvals` 入口也保留共享事项的部门和租户边界。没有任意邀请员工、匿名链接或跨租户共享。
- 共享上下文来自本事项的原始需求、近期 30 条事件和结构化槽位，不读取私人聊天、画像、跨会话记忆。只有申请人的回合可以生成新的受控审批申请；审批人讨论和审批结果回调只允许只读工具。其他外部写工具被前置钩子拒绝。
- 网页在提出申请的消息下显示审批卡片，提供「同意审批」「拒绝申请」「要求补充说明」。前两项提交绑定冻结参数哈希的正式决定；后一项填写协作待办，不改变审批状态（后续扩展见 ADR 0013）。沿用职责分离、双人审批和策略复核，已投票者不能再次投票。讨论中的“同意”没有审批效力。共享事项使用保留的 `task:` 命名空间，私人聊天接口拒绝使用该前缀。
- 两个后台 Agent worker 处理不同事项，每个事项的回合按事件顺序串行。等待审批不占执行槽位。运行租约默认 120 秒并续租，单回合超时 120 秒，失败最多自动尝试 3 次；模型本身仍受既有工具轮数与预算约束。
- 回复、审批草稿与回合完成在同一事务提交；提交前后均检查租约。崩溃后可重新认领事件，过期 worker 无权提交。模型计算可能重复，但不会把同一回合的审批重复写入。
- 独立事件源轮询审批数据库，用审批版本派生唯一事件键；每张正式投票按自身不可变 ID 单独留痕，轮询延迟不会遗漏双人投票。拒绝、过期、策略失效、执行成功、失败或需人工核对，会唤醒原事项的一次只读跟进。独立业务 worker 完成的结果也能被发现。
- `TaskStore.ingest` 接收可信来源的事件，持久化来源、对象与版本游标，拒绝重复和过时状态；事件与待处理回合同事务落库。这是内部扩展接口，不是公开 webhook。新增告警或工单来源只需实现事件源适配器，无需改 Agent 调度器。
- 网页每 2 秒读取共享记录，不依赖打开的浏览器保持任务运行。切换身份或 API 地址会重建页面状态，避免旧身份的异步响应回填。
- 失败回合可以人工重试；已有更新回合开始执行或完成时，不允许再重放旧的失败请求，应发送新消息。申请人或管理员可以停止跟进，这会隔离在途 Agent 提交，但不撤销审批或业务动作；后续投票和结果仍记录在事项中，不再唤醒 Agent。
- 飞书入站处理与出站发送使用独立循环。批量入站中的慢回合不再阻塞已就绪的出站通知。

## 模块边界

| 模块 | 职责与依赖 |
| --- | --- |
| `workflow/tasks.py` | 事项、事件、运行、权限与租约；通过 `TaskEffects` 注入业务效果，不导入审批库或 API |
| `workflow/task_worker.py` | 认领运行、续租、超时与重试；仅调用注入的处理器，不轮询审批 |
| `workflow/task_events.py` | 每个事件源独立轮询；慢源和失败源不占 Agent 执行槽位 |
| `workflow/task_approvals.py` | 审批集成适配器：读取卡片、同事务创建申请、把投票和执行结果转换为事项事件 |
| `agents/task_runner.py` | 事件到 Agent 请求的转换；注入编排器与审批结果读取函数，不依赖 API 全局状态 |
| `workflow/approval_service.py` | 正式审批用例，复用既有审批库与执行 worker；普通审批和事项审批路由共用，不互相调用路由 |
| `api/main.py` | 组合上述组件并管理启动、关闭顺序 |
| `taskClient.js` / `taskController.js` | 分别处理 HTTP 传输和页面状态；投票与讨论有独立的请求状态，切换事项丢弃旧响应 |
| `TaskConversation.vue` / `ApprovalActions.vue` | 分别渲染讨论与审批选项，仅发送事件，不直接请求网络 |

业务解耦保留事务一致性：审批适配器使用任务提交提供的数据库连接，不能先保存回复、再单独创建申请。任务层不配置审批适配器时仍能接收事件和执行普通任务，但会拒绝业务变更提案。

## 验证与限制

`tests/test_shared_tasks.py` 覆盖三方共享、对象权限、跨租户/部门隔离、私人会话命名空间、防止审批人代申请、幂等并发、过期租约、原子提交、审批后恢复、失败重试和事项间调度。另覆盖无审批适配器的事件恢复、旧版本过滤、事件源失败隔离、延迟轮询后的双人投票、拒绝唤醒和停止后的结果留痕。`frontend/tests/taskCollaboration.test.js` 验证审批权限、补充说明草稿、投票与讨论独立、身份快照、跨事项旧响应隔离和发送重试。`tests/test_feishu_channel.py` 的慢回合用例验证发送循环能独立交付通知。

当前实现是网页共享事项，不是飞书群内多人审批；没有主动告警建单、自动审批或自动扩大任务权限。跟进完一轮后进入等待消息状态；ADR 0013 增加进度验收、协作待办和定时唤醒。模型能否完成具体诊断仍需真实模型评测。

身份快照来自收件时已验证的令牌，恢复时仍执行现有业务策略校验，但没有增加 IdP 令牌吊销查询。讨论记录尚未实现分页、保留期或事项级成员邀请。运行次数有界不等于租户费用配额，生产仍需网关限流与配额。
