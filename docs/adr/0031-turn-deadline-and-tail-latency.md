# 0031 整轮截止时间与尾延迟治理

日期：2026-11-13 · 状态：实现已采纳，性能目标未达标

## 背景

单次请求超时无法限制多轮工具循环、声明纠正与故障切换的累计等待。需要限制 Agent 生成预算，同时保留已产生的审批事实；限制等待本身不能证明成功率和成本改善。

## 决定

- 沿用模型路由配置：agent_read 的生成预算为 20 秒，agent_write 为 30 秒，每次模型请求最多 15 秒。默认值在 RouteConfig 声明，读路由在 YAML 中覆盖整轮预算；不增加环境开关。
- BaseAgent 持有整轮截止时间，覆盖工具循环、声明纠正与故障切换。DeadlineModel 只负责将剩余时间传给模型并限制单次请求，不承担审批、路由或统计决策。
- 截止后返回 partial/deadline、重置流式片段；根据成功写工具的实际返回说明草稿或待审批申请。审批仍由既有结算路径落库，后台 worker 的执行与回收独立于聊天生成预算。
- 所有截止退出路径释放当前代的半开模型探测，避免后续请求永久被阻断。整轮预算不包含前置意图识别、记忆读取和后置提交，不能将它描述为 HTTP 端到端上限。
- 声明纠正耗时记录在回合 stage_ms，质量报告展示频率和耗时，不改变纠正规则。保留已有成功率、成本和缓存命中统计。
- benchmark_stream 支持并发和重复次数；compare_latency_cost 在离线报告中匹配数据集与用例重复次数，分别报告真实模型和固定延迟模型结果。流式并发档位不匹配时报错；缺少计划要求的 1/4/8 任一档时，总体验收结果为 null。报告不能以空样本或单个档位宣称全部通过。

## 后果与验收边界

不新增服务、队列、插件层或运行时依赖。生成预算与业务持久化、后台执行保持分离。取消模型请求可能拿不到服务方 token 用量，所以已返回用量的成本只能作为已知成本；存在未报告用量时，完整成本目标保持未测量。

2026-11-13 完成有效配对实测：两组各 330 次用例试验，均通过 312 次；阶段总时延 P99 从 8.552 秒到 8.239 秒，下降约 3.65%，未达到 30% 目标；Agent P99 从 5.820 秒到 5.954 秒。已知 SDK 用量的每成功用例峰值成本从 $0.00072809 到 $0.00072238。没有放宽断言或实施 Jev 阈值实验。正常样本的尾延迟远低于生成预算，截止边界有回归保证，但不能据此承诺常见尾延迟降低 30%。

旧快照凭据缺失导致的认证失败报告已隔离；当前 CLI 在没有凭据时拒绝启动，对比脚本拒绝没有实测 token 用量的窗口。统计只使用修复环境后完整重跑的报告。完整证据、失败样本和外部负载等限制见 docs/improvement-acceptance.md。

- `.venv/bin/ruff check .`、`.venv/bin/pytest -q`。
- 真实模型性能验收按 improvement-plan.md §6.1/6.7：冻结源代码与数据集，在隔离台账中运行两个数据集各三遍，基线与优化后使用相同用例及重复次数；再用 scripts/compare_latency_cost.py 汇总配对应用报告和并发 1/4/8 的流式报告。缺失报告不能通过改名 partial 或复用另一版本结果补齐。
