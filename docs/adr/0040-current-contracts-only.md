# 0040 仅支持当前架构与数据契约

日期：2026-11-16 · 状态：已采纳（修订 0036、0037 的历史兼容安排）

## 决定

当前项目不承担旧部署的兼容升级。替换功能时同步删除旧实现、调用入口、配置和仅验证旧格式的测试；问题在当前架构修复。现有的身份、租户与事项成员隔离、审批审计、资源串行化、租约/CAS、检查点及未知外部写结果回查继续保留。

- 数据库以 `0014` 为全新的独立基线，创建当前 45 张表。删除 `0001`—`0013` 的历史迁移链以及闲置的 `agent_rollouts`、`tenants.policy_ref` 和 `badcases.second_label`。审计只追加约束、执行资源唯一索引、pgvector 和默认租户仍由基线创建。
- 新基线只用于空库；旧 revision 会明确失败，不自动重置、回填、stamp 或转换业务数据。旧库留存原处，使用新数据库启动当前版本。后续变更从 `0015` 继续新增迁移，不反复修改基线。
- 画像只读确定 ID 下的 schema 5；不再搜索任意旧文档或升级 schema 3/4。检查点结果必须包含执行后的 `conversation_state`；事件流绑定必须包含 owner 与 fingerprint。旧 Redis 工作集需要独立命名空间或独立实例，不批量清理其他服务数据。
- 模型工具调用只接受 `tool_calls`。非空旧 `function_call` 在请求、普通响应及流式响应中均拒绝，避免跳过敏感字段处理。
- 归档重放只使用写入事务同步提交的待处理索引，不再扫描迁移旧 Redis 归档。审批策略复核必须有创建时的申请人角色快照，不允许缺失快照时跳过身份约束。
- 管理审计必须明确记录 outcome；取消把 NULL 当作成功。质量报告仅报告单人标注流程使用的指标，删除双人一致性统计。
- 意图评测必须读取完整有效数据集；缺失、空集或坏格式直接失败，不回退到内置小样本。
- 删除无调用的兼容导出、包装函数、协议及前端组件。当前业务测试按契约保留，不按文件年龄删除。

## 使用与验证

旧 SQLite 使用者可设置 `IT_COPILOT_DATABASE_URL=sqlite:///data/it_copilot_current.sqlite3`，指向尚不存在的文件；PostgreSQL 使用独立新建的空数据库。不要把旧库的 revision 强行改成 0014，也不要对含业务记录的库执行 downgrade。若确实需要历史业务数据，应另行设计显式导入和核对流程，不能恢复隐式兼容分支。

运行 `python scripts/dev.py check --profile local` 和专用数据库上的 `--profile postgres`。`test_current_schema.py` 验证新库结构、审计约束、空库重建以及遇到旧 revision 时不修改现有数据；当前任务恢复、资源竞争和租户隔离继续由原业务回归覆盖。协议拒绝行为由 `test_current_contracts.py` 与模型出站测试覆盖。

历史 ADR、冻结输入和长期引用的原始评测证据保留历史含义，不据此恢复旧实现，也不把旧基线结果当作本次验证结论。
