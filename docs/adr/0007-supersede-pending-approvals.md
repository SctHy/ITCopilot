# 0007 同一会话的新申请替代仍待审批的旧申请

日期：2026-10-29 · 状态：已采纳

## 背景

多轮状态评测（docs/evaluation-v3.md 第 7 节）中，用户补充信息、再次说“确认提交”，或要求“补充进工单”时，agent 会重新调用 `create_ticket`。每次调用都会生成一张新的待审批单，审批人逐张批准后就出现重复工单。修复前有 247 段对话，其中 73 段因此失败，占全部 101 个失败的 72%，四种策略都有。

## 决定

- `WorkflowStore.create` 在写入新审批的同一事务里，查找同一会话、同一申请人、仍为 `pending` 的旧审批。如果旧审批的全部动作都被新审批覆盖，就把旧审批标记为 `superseded`。
- “覆盖”按动作键判断：工具 + 目标员工；`request_access` 再加系统。
- 更新带版本号条件：审批人同时决定旧单时，以审批人的决定为准。
- 被替代的审批不能再被批准。双方都记审计（`superseded` / `supersedes`），回复中告知用户。

## 后果

- 修复后的多轮评测中不再出现这类重复工单；用户在同一会话里确实要办的不同事情（例如不同系统的权限）不受影响。
- 新申请范围更窄时不会替代范围更宽的旧单（例如先提交“建单 + 权限”，再提交“只建单”），这种情况仍可能重复，留给审批人处理。
- 跨会话的重复申请不在范围内。
