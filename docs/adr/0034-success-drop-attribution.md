# ADR 0034：成功率波动归因方法

状态：已采纳

## 背景

单看整体成功率不能区分请求构成变化与某类请求的质量下降。Redis trace 会过期，需要基于持久化的回合元数据定位样本。

## 决定

统一使用 `agents.outcome.turn_outcome` 判定成功。按版本、模型、路由、意图、租户、指纹、轮数和 token 分桶，分别计算 `s1*(f1-f0)` 的 rate 贡献与 `f0*(s1-s0)` 的 mix 贡献。每个维度独立，禁止跨维度相加。没有基线的新切片归为 mix 并标记不可比。

提供 Wilson 95% 区间、工具调用错误分母、Token/缓存统计、小时序列、变更前后两小时双比例检验与 Top 切片失败样本。空窗口返回未知，不伪装成零成功率。窗口带时区且不重叠。

## 后果

报告是排查候选原因的工具；时间对齐不证明因果。显著性检验是探索性统计，没有多重校正。样本中的 trace 链接可能过期，长期正文依赖 badcase 快照。

## 验证

`.venv/bin/pytest -q tests/test_attribution.py`：合成模型 X 退化与 model_route 变更显著对齐；纯流量 mix 场景 rate 为零；新切片与空窗口；工具失败使用调用次数作分母。线上真实流量归因：未运行。复现命令见 [runbook](../runbook-success-drop.md)。

2026-11-13 验收补齐缓存归因：命中率下降超过 10 个百分点且 prompt/tools 指纹集合改变时，报告列为优先核查项；无变化不造嫌疑、无样本不判下降。对应正向、低于阈值、空样本及未变指纹反例见 test_attribution.py。
