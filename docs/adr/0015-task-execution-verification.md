# 0015：步骤检查点、独立目标核验与有限重规划

状态：已采纳。

## 背景

共享事项已有持久事件与回合租约，但一个回合中断后仍需重新运行全部 Agent 步骤。工具返回成功、模型回复“已完成”和业务目标达成也不是同一个事实。需要分别处理恢复、当前业务状态核验和最终人工验收。

## 决定

继续使用现有 `TaskStore` 调度事件，通过三个独立边界组合能力：

| 边界 | 实现 | 责任 |
|---|---|---|
| 检查点存储 | `workflow/task_checkpoints.py` | 按回合与步骤保存不可变输入指纹、结果及已知用量；读写均检查当前租约 |
| Agent 恢复适配 | `agents/checkpointing.py`、`agents/task_runner.py` | 冻结回合输入、恢复计划、跳过已完成步骤；不导入数据库表到编排器 |
| 目标核验端口 | `workflow/goal_verifiers.py` 中的 `GoalVerifier` | 校验条件、返回可配置目录、只读观察目标系统 |
| 核验调度与验收门控 | `workflow/task_verification.py` | 独立队列、版本与租约、有限重规划、核验有效期 |
| 组装与传输 | `TaskCapabilities`、`api/main.py`、`api/routes/task_execution.py` | 注入业务就绪判断和适配器；网页不调用 Agent 内部实现 |

检查点、目标与核验记录分别存于 `task_checkpoints`、`task_goals`、`task_verifications`。不把审批状态复制到检查点表；批准和业务执行继续由原审批工作流管理。

## 恢复边界

共享事项回合保存冻结的请求输入、完成的 Agent 调用、最终聚合结果及进度建议。成功结果在租约保护下保存，同一回合重试只运行未完成的部分。

输入指纹不匹配时拒绝复用；目标变更或停止事项后，已取消回合不能追加检查点、审批或回复。模型失败步骤的已知用量单独入账，失败结果不复用。检查点和用量同事务写入；复用结果不会再次收费到任务预算。回合最终回复和审批提案仍由 `TaskStore.finish` 原子提交。

这不是模型内部 token、工具调用中途或任意 Python 指令位置的恢复。如果进程在保存结果前退出，当前步骤会重做。外部业务副作用仍依赖审批执行器的幂等和回查。预算记录已知的 Agent 与进度建议 token；意图识别及进程崩溃前未返回的 provider 用量不构成完整账单。

## 独立核验与网页使用

在共享事项的“目标独立核验”面板配置目标系统和最低角色。只有申请人或 IT 管理员可以修改条件；普通参与者可触发重新核验，观察者只读。系统、角色从服务端策略目录选择，核验对象固定为事项申请人的受信工号，客户端不能指定他人账号或任意 URL。

当前内置 `access_level` 核验器通过业务适配器的 `current_level` 读取实际权限，并按目标系统的角色映射比较最低权限。它不采信 Agent 自述、历史操作成功记录或历史审批结果，也不证明登录、clone、网络访问已经恢复。新增业务目标应实现 `GoalVerifier`，补充受控输入 schema，并在组合根注入。

保存条件和每次 Agent 回合提交都会排队核验；手动核验使用幂等请求键。仍有审批、执行、待办或 Agent 回合未结束时，核验排队等待，不占用模型重规划轮数。核验 worker 的单次读取超时为 20 秒、租约 60 秒；连续三次进程中断后转为需要人工核查。

| 观察结果 | 后续行为 |
|---|---|
| `passed` | 写入独立证据，等待申请人验收，不自动解决事项 |
| `failed` | 按当前目标版本配置的 0–2 轮预算创建只读重规划事件；耗尽后转人工 |
| `unknown` | 无法可靠读取或解释当前状态，直接转人工，不假定成功或盲目重做 |
| `stale` / `cancelled` | 目标、进度、运行状态或租约已变化，结果不能作为验收依据或唤醒旧任务 |

重规划事件隐藏写工具并将 `allowed_writes` 设为空；新业务变更仍须申请人明确发起并经过正式审批。更换目标会取消该旧目标尚未结束的重规划回合。任务累计预算依然在下一次领取前准入，目标变更不会清零累计预算。

配置了条件后，验收必须使用**当前目标版本、当前进度版本、最新一次核验**的通过结果，且结果在五分钟内。进度更新、重新打开事项后需要重新核验。空条件代表人工验收模式，变更留有审计记录。权限可能在核验之后变化；有效期降低陈旧风险，不提供跨系统原子验收保证。

## 验证与复现

```bash
.venv/bin/pytest -o addopts='' -q tests/test_task_execution.py
.venv/bin/python scripts/evaluate_long_tasks.py --repeats 3 \
  --output /tmp/it-copilot-long-tasks.json
```

契约测试覆盖断点恢复、冻结输入、费用去重、失败步骤重试、租约到期回滚、并发领取和结算、版本失效、审批等待、角色和租户权限、只读重规划、核验超时与人工验收。相同测试可设置 `IT_COPILOT_TEST_DATABASE_URL` 在 PostgreSQL 运行。

故障评测在 Agent 调用已持久化、进度建议生成期间用真实 `SIGKILL` 终止子进程，再启动新进程并推进逻辑租约时钟。对照组不启用检查点；实验组启用检查点。其余三种场景分别验证模型误报成功、实际权限达标和核验器不可用。每个场景默认重复三次，共 15 次；输出每次的恢复结果、调用数、复用步骤、重规划次数和错误验收数。

评测使用确定性 Agent、隔离 SQLite 和本地业务适配器，不调用真实模型，不写生产系统。不能用这些数字推导真实模型成功率、生产可用性或真实 provider 费用的改善。
