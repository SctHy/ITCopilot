# 0013 事项进度、协作待办、定时提醒与运行治理

日期：2026-11-11 · 状态：已采纳

后续扩展：[ADR 0014](0014-task-product-capabilities.md) 已补充站外通知、成员管理、附件、历史分页、待办调整与 Agent 建议；本文原始范围限制以该扩展为准。

## 问题与决定

持久化事件与回合已解决恢复问题，但共享事项还需要完成标准、待办归属、无消息时的提醒及累计资源控制。按独立业务能力扩展，不把逻辑塞入 Agent 或前端审批卡片。

| 模块 | 数据所有权 | 交互方式 |
| --- | --- | --- |
| TaskProgressService | task_progress | 版本检查更新步骤；引用事项证据；申请人/管理员验收或重新打开 |
| TaskCollaborationService | task_todos、task_reads | 指定人员答复；追加只读跟进事件；维护个人阅读位置 |
| TaskReminderService | task_timers | 持久化到期时间；通过独立事件源交付提醒或复查事件 |
| TodoDeadlineSource | 待办到期标记 | 到期提醒一次，已答复不提醒 |
| ApprovalDeadlineSource | 审批临期事件 | 在审批集成模块内检查到期时间，不提交投票 |
| TaskGovernance | task_budgets、task_attempts | 同事务认领预算与记录尝试；完成时记账；超限进入 held |
| TaskCapabilities | 组合规则，不拥有审批状态 | 聚合网页数据；验收前检查审批和待办；关闭时取消提醒并终止运行记录 |

`TaskStore.transaction` 提供统一对象授权和行锁；`record` 在同一事务写事件及可选运行。省略 principal 仅用于可信后台适配器。各服务都可独立构造；任务内核不导入扩展服务。`api/main.py` 负责组合，任务 Worker 不知道审批、待办或定时器内部结构。

## 行为约束

- 步骤使用 todo / working / done。done 必须引用当前事项中的证据 ID；证据归属校验不等于自动证明内容正确。最终解决由申请人或管理员提交验收说明。未完成步骤、阻塞、未答复待办、待审批或未结束的执行会阻止验收。
- Agent 读取独立进度和最多 30 条证据摘要（每条最多 1500 字符），不受最近 30 条讨论窗口影响。该上下文不授予写权限；Agent 不自动标记事项已解决。
- 提问只能指派给申请人、当前发起人或已以可信身份参与事项的人；答复时再次校验当前访问权限。只有被指派者能答复。答复重复提交不会重复唤醒，其他内容的重复提交返回冲突。
- “要求补充说明”只预填待办表单。用户提交表单才创建待办；不会自动投票或退回审批。答复和定时事件的 Agent 回合均只读。
- 提醒投递目标为共享网页事项。持久事件本身提供可恢复的站内交付，未读位置按人保存；本次没有外部 IM 或邮件推送。
- 定时提醒的状态更新与事件追加同事务提交。待办答复与超时检查持有同一个事项锁，避免重复提醒。审批临期提醒使用独立事件 ID 去重，已决定的申请不提醒。
- 停止和解决都会隔离在途结果、取消 queued/running/held 回合和手动定时器；审批及业务执行遵守自身生命周期。重新打开不会重放已取消的回合或定时器，可发新消息继续。
- 默认预算为每事项 30 次执行尝试与 200000 已知 token。失败、重试、崩溃前已认领的尝试都计次数，手工重试不重置累计额度。达到任一阈值后后续回合进入 held，其他事项仍可执行。
- token 用量按模型返回值累计，输入 token 已包含缓存部分，不额外重复累加缓存 token。阈值在启动下一回合时检查，当前回合可能超限。超时或崩溃时未知用量明确标注，不伪装成零成本；未实现供应商账单对账或金额硬封顶。
- 尝试日志只保存工具名称、成功标志和耗时，不复制工具输入输出中的凭证。API 返回最近 100 次尝试，数据库保留全部记录。事项列表仍为最近 100 条，历史讨论分页与保留期是后续扩展。

## API 与前端

`GET /task-inbox` 提供未读、待我补充和待我审批计数。`/tasks/{id}` 下新增 `/workspace`、`/progress`、`/lifecycle`、`/todos`、`/todos/{todo}/answer`、`/read`、`/reminders`、`/reminders/{timer}/cancel`、`/budget`。

前端的 TaskDetails 只组合四个面板，面板通过注入的 action 函数提交。taskDetailsController 管理独立请求状态、幂等键和过期响应；taskClient 管理 HTTP 路径。编辑进度时保留草稿版本，不被两秒轮询覆盖，冲突时要求刷新后重新编辑。

## 验证

`tests/test_task_capabilities.py` 可在 SQLite 和 PostgreSQL 运行，覆盖授权、验收与重开、证据归属与长期上下文、待办并发答复、定时恢复/去重、关闭取消、预算暂停/恢复、崩溃记账和审批临期提醒。前端测试覆盖并发独立、请求键保留和卸载后的旧响应隔离。

`scripts/evaluate_shared_tasks.py` 包含 10 个场景，每个默认 3 次。使用应用 lifespan 与 HTTP 接口分别模拟申请人、审批人和管理员。默认替换任务处理器验证基础设施；`--live` 使用真实 Agent，业务操作在临时 SQLite 本地目录中执行。报告明确区分模型模式、业务适配器和 HTTP/浏览器边界。此评测不是 PostgreSQL、浏览器或生产 IdP 的替代。
